## About this artifact

Re-derived on 2026-08-03 against the renderer as it stands after the PR #64 review gate. The run was
not re-taken and no measured value changed. What changed is what the report says about them.

The trend figure is the same number the run produced, printed as what it is. It was published as
`paceDriftMsPerMinute`, the publisher's media clock running against wall clock, and it cannot be
that: it is the first sample's latency minus the last, which is why the scatter beside it is 5.4
times its size and why swapping which segment landed last turns it into -980. The scatter was
computed here from the stored totals over the run's own 63576ms span, which is exact arithmetic on
the old figure rather than a new measurement.

The impossible-hop guidance previously read "The totals are unaffected; the skew estimate or the log
pairing is what to distrust." Both halves were wrong, and the code no longer emits either. The skew
estimate cannot close a 747ms gap it bounded at 200ms, and whether the totals survive depends on
which input is wrong. The headline now also says that the sample it split is one of the flagged ones,
which the previous version left for a reader to notice.

Per-segment raw instants are absent from the JSON, because this run predates the field. Only
durations were recorded, so the run's absolute timings cannot be recovered from it and the span above
had to be inverted out of the old drift figure. Later runs persist `split.instants`.
